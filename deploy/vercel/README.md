# Deploy to Vercel

Generated by `python -m src.export_onnx`. Do not edit `index.html` here - edit
`web/index.html` in the project root; the export copies it over.

## One time

```bash
npm i -g vercel
vercel login
```

## Every deploy

```bash
python -m src.export_onnx --checkpoint outputs/resnet18_ft/best.pt
cd deploy/vercel
vercel deploy --prod
```

## Why ONNX and not PyTorch

Vercel's Python functions cap at 500 MB uncompressed. The PyPI `torch` wheel for
Linux bundles CUDA and blows straight past that; the CPU-only wheel fits but is
~200 MB and takes seconds to import on every cold start. ONNX Runtime is ~15 MB
and starts in about a second, so cold starts are tolerable and the bundle is not
close to any limit.

## The 4.5 MB body limit

Vercel rejects request bodies over 4.5 MB, and phone photos routinely exceed it.
The page downscales every image to 640px on a canvas before uploading, which puts
typical uploads under 150 KB. That is not just a workaround - the model crops to
224px anyway, so uploading the original was always wasted bytes.

Note the canvas is filled white before drawing, because exporting a transparent
PNG to JPEG otherwise turns transparency black - the same trap `load_image_rgb`
avoids server-side.
